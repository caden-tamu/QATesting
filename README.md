# QATesting

This repository is a practice space for our team to learn the GitHub and Git
workflow before starting our future project.

## Workflow

1. Clone the repository and create a branch for each task.
2. Make small, focused changes and commit them with clear messages.
3. Push the branch to GitHub and open a pull request.
4. Ask a teammate to review the pull request.
5. Resolve any requested changes, then merge the pull request.
6. 6. Test

## Getting started

```bash
git clone <repository-url>
cd QATesting
git switch -c <branch-name>
```

Use descriptive branch names, such as `feature/team-practice`, and keep
commits small enough to review.

## Team practice

- Create an issue before starting a larger task.
- Assign the issue or pull request to the appropriate teammate.
- Add comments with useful context and link related work.
- Use pull request reviews rather than pushing directly to the main branch.
- Confirm that all feedback is resolved before merging.

For Git help, see the Git documentation:
<https://git-scm.com/docs>.
